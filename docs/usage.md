# ExcelDB 使用流程

Windows x64 的交付物是单文件 `exceldb.exe`。目标机器不需要安装 .NET、SDK、protoc、Node、Python 或 Unity。同一个 EXE 同时提供 Project Hub、CLI 和 BAT 调用。

## 1. 打开或初始化项目

双击 `exceldb.exe` 会打开 Project Hub。依次完成：

1. 选择一个项目目录，或从“最近项目”中选择；
2. 对空目录点“初始化”；
3. 从首页四张卡片进入 Schema、Excel、Generated C#、Generated Bytes；
4. 需要诊断时再展开“高级／诊断”。

初始化也可以完全非交互执行：

```bat
exceldb.exe init "D:\Game Config"
```

若生成 C# 应直接进入宿主工程，在初始化时选择或指定真实目录：

```bat
exceldb.exe init "D:\Game Config" ^
  --generated-csharp-dir "E:\Unity Project\Assets\Generated\ExcelDB"
```

此时 Generated C# 卡片直接打开外部目录，项目内不会创建一个无效的 `Generated\CSharp` 副本。

便携与安装后调用的 BAT 示例：

```bat
init-with-portable-exceldb.bat "D:\Game Config"
init-with-installed-exceldb.bat "D:\Game Config"
```

对应文件是 [`init-with-portable-exceldb.bat`](../samples/init-with-portable-exceldb.bat) 和 [`init-with-installed-exceldb.bat`](../samples/init-with-installed-exceldb.bat)。不传目录时以当前目录为目标；可选的第二个参数是 Generated C# 真实目录。

## 2. 只认识四类工件

默认布局为：

```text
<ProjectRoot>\
├─ Schema\
├─ Excel\
└─ Generated\
   ├─ CSharp\
   │  ├─ Authoring\
   │  ├─ Runtime\<target-id>\
   │  └─ codegen.manifest.json
   └─ Bytes\
      └─ <target-id>\
         ├─ config.bytes
         └─ config.bytes.manifest.json
```

`Generated` 只是两个生成类别的共同父目录。不要再创建 Config、Data、Import 或 Build 等同义目录。

工具内部状态位于 Windows 默认隐藏的 `.exceldb`：

- `.exceldb\project.json`：四个工件目录的项目设置；
- `.exceldb\published`：需要版本化的发布历史；
- `.exceldb\cache|plans|reports|recovery`：可删除的本地状态；
- `.exceldb\system-imports.json`：系统 proto 编辑镜像的所有权记录。

普通使用者不需要手工编辑这些文件。Project Hub 提供“项目设置”“打开项目配置”“打开报告”“打开内部目录”和“清理缓存”。旧根部 `ExcelDb.Project.json` 不会自动迁移；请重新初始化 Project v2。

## 3. 创建或编辑表结构

日常建表只输入简单字段；默认初始化器会补充 `id` key：

```bat
exceldb.exe table create Hero --workbook Excel\game.xlsx ^
  --field name:string --field hp:int32
```

若要显式声明 key，下面两种写法等价，并且都关闭自动 key：

```bat
exceldb.exe table create Hero --workbook Excel\game.xlsx ^
  --field id:string:key --field name:string

exceldb.exe table create Hero --workbook Excel\game.xlsx ^
  --key id:string --field name:string
```

增加、改名或删除字段：

```bat
exceldb.exe table edit game.configs.Hero --add speed:float
exceldb.exe table edit game.configs.Hero --rename 2:display_name
exceldb.exe table edit game.configs.Hero --remove 3
```

复杂结构以 `Schema` 中的业务 `.proto` 为事实源。业务 proto 继续使用标准导入名：

```proto
import "exceldb/options.proto";
```

ExcelDB 会把内置的 `exceldb/options.proto` 和完整 Google proto 依赖镜像到 `Schema` 供 IDE 跳转。它们默认隐藏、只读且被 Git 忽略，不是项目事实源，也不会参与 schema hash。IDE 若提示 import 不存在，运行：

```bat
exceldb.exe project repair-imports
```

缺失或旧版镜像会由初始化、`generate` 或上述显式修复安全补齐；被修改的镜像、伪造的所有权记录或未登记的 reserved import 会阻断结构写入，并要求显式修复。编译器始终只信任 EXE 内的 canonical catalog，不会采用项目中的镜像副本。

## 4. 重新生成 C# 和 Excel 结构

结构改变后执行：

```bat
exceldb.exe generate
```

一次 `generate` 会：

- 编译当前业务 proto；
- 补齐系统 proto 编辑镜像；
- 更新 manifest 拥有的 Generated C#；
- 同步 `Excel` 下全部 workbook 的结构并保留业务单元格。

它不会修改业务 proto、RowGuid 或 bytes，也不会再次运行建表初始化器或导出目标策略。未知 C# 文件不会被清理；与待生成路径碰撞时会报告 blocker。

## 5. 在 Excel 中填数据

打开生成的 `.xlsx`，从第 4 行起填写业务列。ExcelDB 会递归发现 `Excel` 下的 `.xlsx`，并排除 `~$` 临时文件和隐藏工具文件。

新行的 `__guid` 保持空白。填写完成后显式准备身份并检查：

```bat
exceldb.exe data prepare
exceldb.exe check
```

`data prepare` 只给新增行写入稳定身份；`check` 是只读检查。需要把临时输入规范化到 canonical 表达时使用：

```bat
exceldb.exe normalize
```

复杂消息会展开为普通列；重复消息和 message-map 使用独立子表。内部引用使用稳定 token：

```text
<table-id>:<UTF-8 percent-encoded key components>
```

例如 `101:sword`；复合 key 使用未转义的 `|` 分隔，key 内容中的 `|` 写成 `%7C`。

## 6. 按 target 生成 bytes

client 与 server 都使用派生目录：

```bat
exceldb.exe convert
exceldb.exe convert --target server
```

结果分别是：

```text
Generated\Bytes\client\config.bytes
Generated\Bytes\server\config.bytes
```

每个 bytes 都有同目录的 `config.bytes.manifest.json`。未来合法 target 也自动落入 `Generated\Bytes\<target-id>`；target 必须匹配 `^[a-z][a-z0-9-]*$`。

`--out` 仅作为高级单次覆盖，不会改变项目配置：

```bat
exceldb.exe convert --target server --out "D:\one-off\config.bytes"
```

## 7. 项目设置与诊断

CLI 与 Project Hub 使用同一项目服务。常用高级入口：

```bat
exceldb.exe project inspect
exceldb.exe project configure --generated-csharp-dir "E:\Host\Generated\ExcelDB"
exceldb.exe project repair-imports
exceldb.exe project clean-cache
```

`project inspect` 显示四类工件的真实路径、数量和状态；外部 C# 路径会明确标记。清理缓存、最近项目记录和打开报告都不会改动四类工件。

## 8. 冻结计划与 CI

危险写操作可先预览并冻结计划：

```bat
exceldb.exe generate --dry-run --plan .exceldb\plans\generate.json
exceldb.exe generate --apply-plan .exceldb\plans\generate.json
```

计划会覆盖项目根、外部 Generated C# 根、项目配置、系统 catalog 和输入 fingerprint。输入变化时以 stale blocker 拒绝；v1 冻结计划不会被 v2 执行。跨目录写入的承诺是“全部成功或可恢复”。

CI 最小流程：

```bat
exceldb.exe schema build --check --json .exceldb\reports\schema-check.json
exceldb.exe check --json .exceldb\reports\workbook-check.json
exceldb.exe convert --target client --json .exceldb\reports\convert-client.json
exceldb.exe convert --target server --json .exceldb\reports\convert-server.json
```

完整样例见 [`samples/ci`](../samples/ci) 和 [`samples/git`](../samples/git)。退出码：`0` 成功、`1` 数据错误、`2` blocker/stale、`3` 用法或环境错误。

确认兼容性并准备推进版本化发布历史时，显式执行：

```bat
exceldb.exe schema publish
```

只有该发布操作会推进 `.exceldb\published`；普通 `generate`、`convert` 和 `project repair-imports` 都不会暗中改变发布历史。

## 9. 用简单 C# 扩展默认策略

自定义发行版通过普通 C# 实现 `ITableInitializer` 或 `IExportTargetStrategy`，在 composition root 注册；项目中不再维护复杂声明文件：

```csharp
using ExcelDb.Cli;
using ExcelDb.Schema.Authoring;

return await ExcelDbToolHost.RunAsync(
    args,
    static builder => builder
        .UseTableInitializer(new GameTableInitializer())
        .UseExportTargetStrategy(new GameExportTargets()));

sealed class GameTableInitializer : ITableInitializer
{
    public string Id => "game.table:v1";

    public void Initialize(in TableInitializationContext context, ITableDraft draft)
    {
        new DefaultTableInitializer().Initialize(in context, draft);
        draft.AddField(new SimpleFieldDefinition("source", SimpleFieldType.String));
    }
}

sealed class GameExportTargets : IExportTargetStrategy
{
    private static readonly string[] Targets = ["client", "server", "lite-client"];
    public string Id => "game.targets:v1";

    public void Apply(in ExportTargetStrategyContext context, IExportTargetDraft draft)
    {
        draft.TryFillTableExportTargets(Targets);
        var inherited = draft.TableExportTargets!.Targets;
        foreach (var field in draft.Fields)
            draft.TryFillFieldExportTargets(field.Name, inherited);
    }
}
```

这些类型随受信任的自定义 EXE 一起编译；标准 EXE 不扫描项目 `.cs`、外部程序集或声明式 profile。初始化器只填充尚未冻结的简单建表意图；导出策略只决定字段面向哪些 target。确认结构写入业务 proto 后，`generate`、`check` 和 `convert` 读取该结构，不会偷偷重新运行策略。
