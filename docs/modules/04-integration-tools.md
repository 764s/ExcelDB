# 模块 4：集成工具（Project Hub / CLI / Unity / CI / VCS）

设计状态：**Dependency-Complete**；实现状态：**Pending verification**。本文是 M4 集成工具投影的唯一 owner；工具只投影 M2/M3/M5-M8 已定义的领域操作，不发明第二套 schema、workbook、convert 或 runtime 语义。跨模块权威规则与架构决策见 [`docs/spec/README.md`](../spec/README.md)。

## 1. 产品入口与覆盖原则

- 首要交付是按 Windows RID 发布的纯 C# self-contained 单文件 `exceldb.exe`。用户可把它复制到任意位置后双击，也可安装后从 BAT/CLI 调用；两种入口使用同一服务与 OperationReport。
- Windows 交互环境无参数启动时打开原生 WinForms Project Hub。带参数启动始终执行 CLI；stdin/stdout 被重定向或非交互环境无参数启动时打印用法并退出 3，不打开窗口、不等待输入。
- Project Hub 是可反复返回的操作首页，不是线性阶段向导，不保存“做到第几步”。它从 Project 配置和现有工件推导状态，提供当前可执行动作及禁用原因。
- 同一操作的 Hub、CLI、Unity 投影必须调用同一 typed application service，产生同一 MutationPlan、OperationReport 和领域工件；禁止启动子进程、解析控制台文本或实现 UI 专属写入。
- 取消文件夹选择、关闭窗口、取消计划确认和只读 Inspect 都必须零写入。

### 1.1 场景覆盖

| 场景 | 普通用户入口 | 自动化入口 | 结果 |
| --- | --- | --- | --- |
| 选择空目录或已有 Project | Hub“选择项目目录”/最近项目 | `--project`、`project inspect` | 只读 `ProjectInspection` |
| 初始化 | Hub“初始化项目” | `init [path]` | 四类工件目录、Project v2、系统 import 镜像 |
| 新建/维护表 | Hub“创建/编辑表结构” | `table create/edit` | candidate proto + 同一计划 |
| 重新生成 | Hub“重新生成” | `generate` | descriptor、C#、Excel 结构、系统 import 镜像 |
| Excel 新行身份 | Hub“准备新增行身份” | `data prepare` | 只写计划内 `__guid` |
| 检查 | Hub“检查数据” | `check` | 只读诊断与报告 |
| 生成运行时数据 | Hub 选择 target | `convert [--target]` | 单 target bytes + manifest |
| 系统 import 修复 | Hub“一键修复” | `project repair-imports` | 只修工具拥有的编辑镜像/记录 |
| 配置 C# 输出 | Hub“项目设置” | `project configure --generated-csharp-dir` | 只改 Project 配置，不搬旧文件 |
| Git/CI | 报告跳转 | `diff` 与命令组合 | 不增加 Project 配置键 |

## 2. Project v2 与四类用户工件

唯一 Project 配置位于 `<ProjectRoot>/.exceldb/project.json`，进版本控制，未知键、缺键、重复键或 `formatVersion != 2` 均为用法/配置错误。canonical 内容恰为：

```json
{
  "formatVersion": 2,
  "schemaDir": "Schema",
  "excelDir": "Excel",
  "generatedCSharpDir": "Generated/CSharp",
  "generatedBytesDir": "Generated/Bytes"
}
```

四个目录字段恰好对应普通用户关心的四类工件：

```text
<ProjectRoot>/
├─ Schema/
├─ Excel/
├─ Generated/
│  ├─ CSharp/
│  │  ├─ Authoring/
│  │  ├─ Runtime/<target-id>/
│  │  └─ codegen.manifest.json
│  └─ Bytes/<target-id>/
│     ├─ config.bytes
│     └─ config.bytes.manifest.json
└─ .exceldb/
   ├─ project.json
   ├─ system-imports.json
   ├─ published/
   ├─ cache/
   ├─ plans/
   ├─ reports/
   └─ recovery/
```

规则：

- `schemaDir`、`excelDir`、`generatedBytesDir` 必须解析到 Project 根内；`generatedCSharpDir` 可位于 Project 外。全部路径先 canonicalize，并拒绝 `..`、symlink/junction/reparse-point 逃逸声明根。
- Project 内目录使用 Project-relative 路径；初始化/设置选择项目外 C# 目录时一律保存 canonical 绝对路径，并明确提示该配置与机器相关。只修改配置，不移动或删除旧输出；用户随后显式执行 `generate`。
- 若 C# 根位于项目外，不创建项目内 `Generated/CSharp` 占位目录；Hub 的 Generated C# 卡直接打开真实目录。
- `excelDir` 下递归发现 `.xlsx`，排除文件名以 `~$` 开头的 Office 临时文件、Hidden 文件、`.exceldb` 工具内容与符号链接逃逸；不再配置 workbook glob。
- bytes 默认路径由 `<generatedBytesDir>/<target-id>/config.bytes` 唯一派生。`client`、`server` 与未来合法 target 使用相同规则，不增加 Project 键。
- `.exceldb/published` 保存 M8 必须版本化的 descriptor 历史；`.exceldb/cache|plans|reports|recovery` 是可删除本地状态并由 `.exceldb/.gitignore` 忽略。`project.json`、`system-imports.json` 和 `published` 不得被该 ignore 排除。
- `Schema/.gitignore` 忽略 `/exceldb/` 与 `/google/protobuf/` 系统镜像；业务 proto 和 Excel 继续进版本控制。生成 C# 是否入库遵循 M3；Generated Bytes 默认忽略并由构建重建。
- Windows 初始化和每次 Project 打开都幂等修复 `.exceldb`、`Schema/exceldb`、`Schema/google/protobuf` 的 Hidden 属性及系统 proto 文件的 ReadOnly 属性。属性失败只产生 warning，不改变领域内容或编译结论。
- 根部 `ExcelDb.Project.json`、无 `formatVersion` 或旧五键形态只识别为 legacy v1。工具给出“重新初始化或手工整理”的准确诊断并零写入，不自动迁移、不静默兼容。

## 3. Project Hub

### 3.1 项目选择与最近项目

- 首页顶端提供“选择项目目录”；使用系统文件夹选择器，取消零写入。选择目录后立即只读 Inspect，再决定是否启用初始化或其他操作。
- 最近项目保存在 `%LOCALAPPDATA%/ExcelDB/launcher-state.json`，最多 10 个，按最后成功选择时间降序并按 canonical path 去重；提供逐项移除和全部清空。
- 本机状态只记录 canonical Project 路径与时间，不保存 schema、target、操作阶段、窗口业务值或生成输入。文件缺失/损坏按空状态恢复；不存在路径标记不可用但不自动删除。任何状态变化不得改变 Project 工件。

### 3.2 四张工件卡

首页严格显示以下四张卡，不出现 Config、Data、Import、Build、cache 或“内部文件”作为同级分类：

1. **Schema**：路径、proto 数量、编译/系统 import 状态、“打开目录”。
2. **Excel**：路径、workbook 数量、pending/error/drift 摘要、“打开目录”。
3. **Generated C#**：真实路径、manifest/schema 新鲜度、是否为外部目录、“打开目录”。
4. **Generated Bytes**：路径、各 target 工件状态、“打开目录”。

卡片下方固定提供：初始化、创建表、编辑表、重新生成、准备新增行身份、检查数据、生成指定 target bytes、修复 Proto 依赖、项目设置。按钮由 `ProjectActionAvailability` 决定；禁用时必须展示原因，不能以点击后才报错替代状态说明。

“高级/诊断”默认折叠，仅提供打开项目配置、打开 `.exceldb`、打开最新报告、打开 recovery、清理 cache。发生错误或需要恢复时，在对应动作旁直接提供“查看报告/恢复”链接，用户不必先寻找隐藏目录。清理 cache 不得清理 Project 配置、published、system-imports、计划确认对象或未完成 recovery。

### 3.3 设置与初始化窗口

- 初始化窗口明确显示 Project 根和 Generated C# 输出位置，后者提供文件夹选择；摘要预览四类真实路径、外部目录警告和完整 MutationPlan。
- 项目设置重点编辑 Generated C# 输出；其他三个目录显示解析后的高级路径并可编辑。保存走同一个 `PlanConfigure`：写入 `.exceldb/project.json`，并补齐新声明根所需的目录、`Schema/.gitignore`、系统 proto 编辑镜像及其所有权记录；不得搬运或删除旧根中的用户工件，也不得重跑表初始化器或导出目标策略。
- 打开目录/配置/报告使用 shell 只读跳转；路径不存在时给出原因，不为“打开”动作暗中创建目录。

## 4. 共享 application service

Hub 与 CLI 共用 typed 服务；宿主可以增加 adapter，但不得改变操作语义：

```csharp
public interface IExcelDbProjectService
{
    ProjectInspection Inspect(ProjectLocation project);
    OperationReport RepairProjectOwnedAttributes(ProjectLocation project);
    MutationPlan PlanInitialize(InitializeProjectRequest request);
    MutationPlan PlanConfigure(ConfigureProjectRequest request);
    Task<MutationPlan> PlanCreateTableAsync(CreateTableRequest request, CancellationToken cancellationToken = default);
    Task<MutationPlan> PlanEditTableAsync(EditTableRequest request, CancellationToken cancellationToken = default);
    Task<MutationPlan> PlanRegenerateAsync(RegenerateRequest request, CancellationToken cancellationToken = default);
    Task<MutationPlan> PlanDataPrepareAsync(DataPrepareRequest request, CancellationToken cancellationToken = default);
    MutationPlan PlanRepairSystemImports(RepairSystemImportsRequest request);
    Task<OperationReport> CheckAsync(CheckRequest request, CancellationToken cancellationToken = default);
    Task<OperationReport> ConvertAsync(ConvertRequest request, CancellationToken cancellationToken = default);
    OperationReport CleanCache(ProjectLocation project);
    OperationReport Apply(MutationPlan plan);
}
```

`Inspect` 始终只读；Project Hub 在识别出有效 Project 后另行调用 `RepairProjectOwnedAttributes`，只幂等修复工具自有的 Windows Hidden/ReadOnly 属性。CLI `project inspect` 不调用该修复入口。

`ProjectInspection` 至少包含 Project 根、四类已解析路径、配置/legacy 状态、系统 import 状态、每类摘要、最近报告/恢复提示和各动作可用性。`ProjectStatus` 必须能区分：未初始化、legacy/配置错误、待 recovery、无表、系统 import 缺失/旧版/冲突、需重新生成、存在 pending-new、数据错误、就绪。

### 4.1 `generate` 的统一语义

`generate` 形成一个不可变计划并依次暂存：

1. 从当前业务 proto 和 EXE 内 M1 system catalog 编译 candidate descriptor；
2. 修复 catalog 拥有的系统 proto 编辑镜像和 `.exceldb/system-imports.json`；
3. 生成 `<generatedCSharpDir>/Authoring`、`Runtime/<target>` 与 codegen manifest，并只清理旧 manifest 明确拥有的文件；
4. 同步 `excelDir` 下全部受管 workbook 的 schema-owned 结构。

它不得修改业务 proto、业务 cell、RowGuid 或 Generated Bytes，不得运行 `ITableInitializer`/`IExportTargetStrategy`，不得删除未知 C# 文件。任一阶段 blocker 时全部领域目标零替换；项目外 C# 根使用 §5 的多根事务。

## 5. MutationPlan v2 与多根恢复事务

C1/C3/C4/generate/normalize/data prepare/configure/repair 的领域写入共享 canonical `MutationPlan` v2：

- 每个 mutation/observation 使用 `root = Project | GeneratedCSharp` 加 root-relative `/` 路径，不存可随机器变化的拼接绝对文件路径。计划 header 明确记录两个解析后声明根、Project/config hash、ToolVersion、system catalog hash、schema hash、全部 source/target fingerprints、风险、确定序 mutation 和 `planHash`。
- `GeneratedCSharp` 与 `Project` 解析为同一物理根时仍规范化为单根提交；外部目录在预览中醒目标示。所有 root-relative 路径必须在 revalidate 和 commit 前再次拒绝绝对路径、`..`、symlink/junction 逃逸。
- 交互只收集一次意图，生成内存计划，完整展示并确认后 Apply 同一对象；取消零写入。CLI `--dry-run --plan` 与 `--apply-plan` 使用同一 canonical 序列化；v1 计划明确拒绝，不隐式升级。
- Apply 先验证 planHash、配置、catalog 和全部 fingerprints，再为每个根建立同卷 staging/backup。所有根预备成功后写 recovery journal 并依序替换；任一失败立即按 journal 逆序回滚。
- 进程中断留下 `.exceldb/recovery` 时，下一次 Hub/CLI 启动必须在其他写操作前完成或回滚恢复；恢复未解决时所有写按钮/命令禁用，Inspect/查看报告仍可用。
- 跨根契约是“全部成功或可恢复”，不是跨磁盘瞬时原子可见。成功报告只有在全部根提交且 journal 清理后产生。
- codegen 只能删除 `codegen.manifest.json` 有效记录的拥有文件。未知文件、损坏 manifest、目标碰撞和无法证明 ownership 都是 blocker。

## 6. CLI 契约

### 6.1 命令全集

| 命令 | 行为 |
| --- | --- |
| `init [path] [--generated-csharp-dir <path>]` | 计划/初始化 Project v2 和四类目录 |
| `project inspect` | 只读输出 ProjectInspection |
| `project configure [--schema-dir <path>] [--excel-dir <path>] [--generated-csharp-dir <path>] [--generated-bytes-dir <path>]` | 计划修改四类目录配置；不搬旧输出 |
| `project repair-imports` | 计划修复 M1 系统 proto 镜像 |
| `schema build [--check]` | 编译当前业务 proto；build 可生成 C#，check 只比较 |
| `table create [name]` | 简单字段/选项 → initializer/target strategy → candidate proto 计划 |
| `table edit [table]` | 结构变更、target membership 与兼容计划 |
| `generate` | 执行 §4.1 的统一重新生成计划 |
| `normalize` | M8 legacy cell canonicalize 计划 |
| `data prepare` | 只固化 pending-new RowGuid 的计划 |
| `check` | 只读全量校验 |
| `convert [--target <id>] [--out <path>]` | 一次生成一个 target 的 bytes + manifest |
| `diff <base.xlsx> <target.xlsx>` | VCS-only 只读对账 |

公共参数：`--project <path>`、`--json <path>`、写操作的 `--dry-run --plan <path>` / `--apply-plan <path>`。退出码固定为 0=ok/warning、1=error、2=blocker、3=用法/环境错误。

### 6.2 Project 与路径解析

- 显式 `--project` 优先；未指定时从 cwd 向上查找最近的 `.exceldb/project.json`。命令行可接受 Project 根或该配置文件路径。
- 无 Project 时只允许 `init`、help/version；legacy 配置不参与向上发现后的兼容运行。
- `init [path]` 和 `--project` 的相对路径按 cwd 解析；Project 选定后其他相对路径按 Project 根解析。
- 省略 `--target` 固定为 `client`。省略 `--out` 时，所有合法 target 均派生到 `<generatedBytesDir>/<target-id>/config.bytes`；`--out` 是本次高级覆盖，不写回 Project。单次命令拒绝 `all`、列表、重复 target 和非法/逃逸 id。
- `--json` 只控制本次 OperationReport 路径；默认报告位于 `.exceldb/reports`，不增加配置键。

### 6.3 建表输入与显式 key

标准建表只收集表名、目标 workbook、显式 key 或 AutoKey、简单字段、封闭自动选项和每字段 client/server 自动/手动选择。`DefaultTableInitializer` 与 `IExportTargetStrategy` 的机制归 M1。

- `--field id:string:key` 必须关闭 AutoKey，并与 `--key id:string` 形成同一 canonical draft；不得再自动添加第二个 `id` 字段。
- 显式 key 与显式 AutoKey 同时给出是用法错误；普通字段未声明 key 且未关闭 AutoKey 时才允许默认 initializer 补 key。
- initializer/strategy 只在计划构造前运行；冻结计划、apply、generate、build、check、convert 不得重跑它们。

### 6.4 单文件离线

单文件内置锁定 parser/compiler、完整 system proto catalog、SchemaCompiler、codegen、xlsx、convert、默认 initializer 与标准 target strategy。在无 .NET Runtime/SDK、PATH protoc、网络和 Unity 的 Windows x64 环境中，仍须完成 init、建表/编辑、generate、data prepare、check、convert。`dotnet tool` 可作为附加安装形态，但不得成为主流程前置。

## 7. Unity、CI 与 VCS 投影

### 7.1 Unity

- Unity SettingsProvider 直接投影 `.exceldb/project.json` 四目录字段，不使用 EditorPrefs 副本；workbook 挂载从 `excelDir` 递归发现。
- Generate、Data Prepare、Check、Convert Client 调用同一服务；计划预览展示 plan hash、声明根、fingerprints、风险与 blocker。Unity 默认运行时 target 仍为 client，但不改变 CLI/Project 的开放 target 规则。
- 报告窗口显示 target、实际 bytes/manifest 路径和可跳转诊断；Project 配置/系统镜像问题提供打开 Hub/配置/报告的入口。
- Browser、dirty/冲突拦截、Play source picker 与 RuntimeDatabase 接线继续遵守 M2/M3/M6/M7，不把宿主状态写进 Project 配置。

### 7.2 CI

```text
I1  exceldb schema build --json .exceldb/reports/schema.json
I2  git diff --exit-code -- <generatedCSharpDir>
I3  exceldb check --json .exceldb/reports/check.json
I4  exceldb convert --target client --json .exceldb/reports/client.json
I5  exceldb convert --target server --json .exceldb/reports/server.json
I6  按 target 隔离上传 Generated/Bytes/<target>/config.bytes + manifest
```

全部要求 target 成功后流水线才发布；一次 convert 仍只处理一个 target。Project v2 不保存 CI 发布矩阵。

### 7.3 VCS

- 建议根 `.gitignore` 忽略 `Generated/Bytes/`；`.exceldb/.gitignore` 只忽略 cache/plans/reports/recovery；`Schema/.gitignore` 忽略系统 proto 镜像。
- `.gitattributes` 对 `*.xlsx binary`；`exceldb diff` 可直接作为 difftool。Git baseline、pre-commit 与 PR 评论脚本是配方，不进入 Project 配置。
- fresh clone 首次打开 Hub 时若镜像缺失，显示“一键修复”；镜像本身不要求进 Git。

## 8. 命令样例

```powershell
# 初始化；C# 默认位于项目内
.\exceldb.exe init E:\GameConfig

# 或直接把 C# 生成到宿主源码目录
.\exceldb.exe init E:\GameConfig --generated-csharp-dir E:\Game\Assets\Generated\ExcelDB

# 检查状态、修复系统 import、生成结构
.\exceldb.exe project inspect --project E:\GameConfig
.\exceldb.exe project repair-imports --project E:\GameConfig --dry-run --plan E:\GameConfig\.exceldb\plans\repair.json
.\exceldb.exe project repair-imports --project E:\GameConfig --apply-plan E:\GameConfig\.exceldb\plans\repair.json
.\exceldb.exe generate --project E:\GameConfig

# 每个 target 自动落到 Generated/Bytes/<target>/config.bytes
.\exceldb.exe convert --project E:\GameConfig --target client
.\exceldb.exe convert --project E:\GameConfig --target server

# 高级的一次性输出覆盖，不改变 project.json
.\exceldb.exe convert --project E:\GameConfig --target server --out E:\Staging\server\config.bytes
```

## 9. 明确不提供

- 不提供根部 `ExcelDb.Project.json` 或 v1 自动迁移。
- 不提供五键配置、workbook glob、逐 target bytes 配置键、target profile/发布矩阵。
- 不提供无参数线性控制台向导、Workspace、Project Hub 插件化阶段或操作历史事实源。
- 不提供动态扫描/编译项目 `.cs` 的 initializer/strategy 插件；普通 C# 扩展编入定制发行物。
- 不提供 `convert all`、从输出路径猜 target、运行时动态重算 target membership。
- 不提供 Excel 插件、CLI watch、内置 Git 三方合并器、游戏内调参 UI 或角色权限系统。

## 10. 模块验收

1. 双击同一 `exceldb.exe` 显示 WinForms Hub 且无控制台线性问答；带参数保持 CLI stdout/退出码，重定向无参数打印用法并退出 3。
2. 首页严格四张卡；选择/取消目录零写入；未初始化、legacy、镜像异常、stale、pending、error 与 ready 状态对应正确按钮和禁用原因。
3. 最近项目排序、去重、10 项上限、缺失路径、移除、清空和损坏状态恢复均不改变 Project 工件。
4. 初始化只产生四类用户目录与隐藏配置/系统镜像；外部 C# 根不创建本地占位。Project JSON canonical 且未知/缺键拒绝；legacy 明确拒绝、零迁移。
5. `excelDir` 递归发现覆盖子目录、`~$`、Hidden、临时/工具文件与 symlink 逃逸。
